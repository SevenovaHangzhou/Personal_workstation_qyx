# 星序 / ORBIT：Linear 关联本地任务使用手册

适用版本：0.10.0 · Linux / Windows。本文功能属于星序工作版，知序 / LUMA 不提供 Linear 入口。

## 先选一种方式

| 你的情况 | 操作 | 结果 |
|---|---|---|
| Linear 已有指派给你的 issue | 拉取 My Issues → 勾选 → 导入 | 创建尚未存在的本地工作任务，并关联原 issue |
| 本地已有工作任务，Linear 也有对应 issue | 任务详情 → 关联一个 issue → 粘贴链接 | 保留本地任务，关联已有 issue |
| 本地新建工作任务，Linear 还没有对应 issue | 配置默认团队，等待 22:00 | 为该任务及工作子任务分别创建 issue |

只有「工作任务」关联 issue。Demo、日常任务保留在星序，但不创建 issue、不向 Linear 上传日报；学习内容属于知序。

## 1. 配置个人 API Key

1. 打开星序，点击任务列表右上方与「新建任务」并列的 **拉取 My Issues**。窄窗口中，这两个按钮会一起排在标题下方。
2. 点击 **创建 / 管理个人 API Key ↗** 打开 Linear 设置。也可在 Linear 的 **Settings → Account → Security & Access → Personal API keys** 创建密钥；个人 API 设置入口为 <https://linear.app/settings/api>。
3. 为密钥命名，例如 `ORBIT 本机`，按用途选择权限与可访问团队。

| 用途 | 所需权限 |
|---|---|
| 拉取 My Issues、读取团队与项目 | Read |
| 22:00 为本地工作任务创建 issue | Read + Create issues |
| 把工作聊天摘要追加为 issue 评论 | Read + Create comments |
| 把已有 issue 调整为子 issue，或移除其父级 | Read + Write |

需要上述全部功能时，选择 Read、Write、Create issues、Create comments，并允许访问实际使用的团队；不需要 Admin。密钥只能访问其所属账号有权访问的数据，团队限制还会进一步缩小范围。若没有创建入口，请管理员检查 **Settings → Administration → API → Member API keys**。权限与设置说明见 [Linear 官方文档](https://linear.app/docs/api-and-webhooks)。

4. 将密钥粘贴到星序的 **Linear 个人 API Key** 输入框，按需保留 **在本机记住密钥**，点击 **连接**。
5. 点击 **拉取 My Issues**。成功显示账号姓名和待导入数量，才表示已完成联网读取验证；仅显示「已配置密钥」不代表已验证密钥有效。

密钥只填入应用输入框，不要写进任务、日报或仓库。点击「忘记密钥」会清除星序保存的凭据；在 Linear 撤销密钥则使该密钥失效。若自行配置过 `LINEAR_API_KEY` 环境变量，也需在系统中单独移除。

## 2. 把已有 My Issues 导入本地

1. 点击 **拉取 My Issues**。已有密钥时，打开窗口会自动拉取。
2. 列表只显示 **指派给当前密钥账号，且尚未关联本地工作任务** 的 issue。
3. 勾选需要的条目，点击 **导入所选 N 项**。首次可只导入一项，核对结果后再批量导入。
4. 回到工作任务列表，打开刚导入的任务；详情中的 **Linear issue** 应显示编号，点击 **打开 issue ↗** 可核对远端。

默认排除已完成、已取消 issue。需要这些条目时，勾选 **包含已完成 / 已取消** 再拉取。

重复拉取会跳过已有本地任务；手动关联、子步骤和已完成的本地任务也参与去重。导入前会再次检查，避免重复创建。此入口只新增缺少的任务，不刷新已有任务的标题、状态或笔记，也不向 Linear 写入内容。导入条目会建立各自的本地任务，不会自动还原整套远端父子结构。

## 3. 为已有本地任务关联 issue

1. 选择一条 **工作任务**，在任务详情的 **Linear issue** 卡片点击 **＋ 关联一个 issue**。
2. 粘贴从 Linear 复制的完整 issue 链接，例如 `https://linear.app/your-workspace/issue/ENG-123/example`。
3. 点击 **关联 issue**，再点击 **完成**。
4. 返回详情，使用 **打开 issue ↗** 检查是否指向正确事项。

每项工作任务与一个 issue 一一对应；同一个 issue 不能再关联另一项本地工作任务。手动粘贴时校验的是链接格式，远端存在性、账号权限及归属会在同步时进一步核对。删除本地任务也不会删除远端 issue。

## 4. 设置新建 issue 的团队与项目

1. 打开左侧 **日报与同步**，点击 **选择默认团队 / 项目**。
2. 选择团队；本项目使用 **电气部门**。如果列表没有它，先检查密钥所属工作区、账号成员权限及密钥的团队访问范围。
3. 项目可选，不需要时保留 **不指定项目**。
4. 确认显示的负责人是你的 Linear 账号，点击 **使用此归属**。
5. 按需启用 **每日 22:00 日报、工作 issue 同步和本地 Git 留存**，并在 **待同步工作任务** 中预览。

API Key 负责访问权限，不会替新安装的星序自动选定默认团队。选择默认团队会启用自动排程；如果已有到期周期，应用可能随即补跑，因此请先核对待同步任务。仅需只读导入时，可以保持自动排程关闭。

新建根工作任务默认使用上述团队与可选项目，负责人为当前 Linear 用户。尚未绑定 issue 的根任务，可展开详情 **更多任务设置 → 选择本任务 Linear 归属** 单独覆盖；工作子任务继承父任务的团队、项目和负责人。已绑定 issue 的归属以 Linear 为准，该入口不会迁移其团队。

## 5. 子步骤与每日同步

- 在任务中点击 **＋ 规划下一步** 创建工作子步骤；每个子任务也是一项独立工作任务，22:00 为尚无 issue 的父任务、子任务各建一个 issue，并保持父子关系。
- 将任务合入另一任务或移为独立任务时，本地立即调整；已有 issue 的父级关系在下一次 22:00 同步。调整父级不会自动改变已有 issue 的团队或编号。
- 步骤图中的前置关系用于本地规划，不会同步为 Linear 的「阻塞 / 被阻塞」依赖。

每日周期按 **Asia/Shanghai** 计算：前一天 22:00 至当天 22:00，22:00 后的聊天计入下一期。

星序只收集明确绑定到本应用任务的 Codex 聊天；其中工作任务的聊天摘要按日期追加到对应 issue 的评论。不会覆盖 issue 描述，也不会根据模型摘要自动判定完成或改变远端状态。需要评论进度时，请先在工作任务中「新建聊天」或「绑定已有聊天」。

关闭主窗口后，托盘仍继续运行。电脑关闭或应用完整退出期间不会执行，下次启动会补跑。可在 **日报与同步 → 日报记录与失败原因** 查看结果，使用 **补跑到期日报 / 重试** 处理已经到期的周期；这个按钮不会提前发布当晚尚未到期的新任务。

侧栏 **下班**、**总结周报** 生成的手动日志只在本地查看，不创建 issue、不上传评论，也不触发 Git 留存。

## 常见问题

| 现象 | 检查方法 |
|---|---|
| My Issues 为空 | issue 是否指派给密钥所属账号；是否属于该密钥可见的团队；是否已完成或已在本地 |
| 找不到电气部门 / 某个项目 | 检查工作区、账号权限及密钥团队范围；项目列表随团队变化 |
| 显示密钥无效或没有权限 | 确认未过期、撤销或复制多余空格，并补齐实际操作需要的权限 |
| 本地任务还没有 issue | 确认分类为工作、默认归属已选、排程已启用、22:00 已到；查看待同步列表与失败原因 |
| 关联后没有评论 | 关联本身不产生进度；需绑定工作聊天、有该周期消息且摘要成功，随后完成到期同步 |
| 远端标题或状态变化没有回填 | My Issues 入口只导入缺少任务，不是已有任务的全量双向同步 |
| 删除了本地任务，Linear issue 还在 | 正常行为；本地删除与远端删除相互独立 |
| 重试提示多重映射或归属已改变 | 核对任务与 issue 的一一对应以及先前同步记录；先解决冲突再重试，不要靠重复新建 issue 处理 |

遇到失败时，先修复网络、密钥或归属，再使用原重试入口；同步账本会核对已成功的 issue 与评论，避免重复创建。
