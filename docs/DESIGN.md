# 星序 / ORBIT 产品设计

原生 Linux 桌面应用，使用雾白、深蓝灰、低饱和青蓝及少量琥珀色，保留圆角、留白和亲切感。七个节点构成开放轨迹，以星点、路径与精密参考线含蓄呼应品牌背景。名称为用户确认的「星序 / ORBIT」，主界面不放公司全称或行业口号。图形和配色详见 BRAND_THEME.md。

把事情拆小，用方向与小步规划、续接笔记与专注计时减少切换成本。主工程内部仍保留 Momo 标识以兼容现有数据；与固定引入的 Work Station 都使用 YomkServerPy，同一 Python 3.11+ 进程内运行。

## 个人事项

今天、全部、工作、学习、有趣 Demo、日常、已完成与关联空间。列表/看板、搜索、日期、四态、步骤、删除、笔记、专注小窗继续保留。

仅工作任务使用 Linear，每个父/子任务各映射一个 issue；允许先创建待同步草稿，22:00 自动创建。其他分类不显示 issue，服务层也禁止新增。已有缺 issue 的工作任务保留，仍可本地执行。跨分类需明确解除本地 issue，保留笔记与步骤；不会删除远端 issue。

My Issues 在工作视图只读拉取当前用户数据，用户勾选后导入，不自动执行。只有工作任务提供 Git 仓库关联；其他分类可以为本次执行选择普通本地目录。

聊天入口为并列的「新建聊天」「绑定已有聊天」两个按钮，有无已有绑定均显示。新建直接进入工作目录选择与创建，不先扫描历史；绑定已有聊天则提供历史搜索、匹配原因、片段与手动链接。历史匹配不调用模型，点击候选才绑定。创建空聊天并绑定后打开 Codex，任务说明复制到剪贴板供粘贴；打开失败可重试打开，不重复创建。多条聊天可以绑定同一事项。

## 方向与小步

入口为「规划下一步」，说明为「列出可以并行的方向，或接下来的一小步」。每行录入，选择「加入并行方向」或「接在选中步骤后」；已有/新增步骤均可改名，并勾选同一父任务内的一个或多个前置步骤。前置依赖单独保存，不把父子包含画成执行顺序。

详情自动展示本层从上到下的原生 DAG；规划窗口实时预览，支持缩放、拖动和适应画布。无前置的方向从开始分出，多前置的步骤形成汇合。点击节点选中，详情缩略图双击可打开子任务；含更细小步的节点显示数量，逐层查看。循环依赖立即拒绝，旧数据不推断顺序。规划保存为一次原子操作，取消不写数据，外部更新引起冲突时保留当前输入。

## 需要我处理

按 2026-10-28 的新决定，移除项目空间、本机执行页，以及新建项目、关联项目、提交执行、重试入口。保留「需要我处理」，查看已有待补充、待验收、失败、退回和待核实记录，可验收已有交付、查看日志与产物。

后台 Yomk 服务、历史记录及同仓库维护互斥保留，继续支持日报与 Git 留存。步骤依赖用于用户规划，不自动驱动执行。

## 生命周期

关闭窗口缩到系统托盘，同进程继续执行与专注。显式退出会停止子进程、等待工作线程、关闭服务、连接和日志。托盘不可用且仍有执行时保留最小化窗口。

异常退出的在途记录先进入“状态待核实”，不会自动重投。删除个人任务独立于停止执行，确认框说明执行记录仍保留。个人任务的专注时长与后台执行时间分别存储，不相互累加。

完整融合决定与下一阶段边界见 `WORKSTATION_INTEGRATION.md`；实施状态见 `IMPLEMENTATION_TASKS.md`。

## 日报与留存

新增「日报与同步」原生窗口，选择默认团队和可选项目后每晚 22:00 自动运行。本地收集所有分类，只有明确绑定工作任务的聊天摘要追加到对应 issue。晚间新增聊天进入次日日报。代码采集、匹配与重试不依赖模型，只有必要文本压缩使用系统 Codex。

独立子任务替代单一下一步；父级与子级可分别绑定聊天、管理状态。Git 对显式关联本地仓库的未完成工作事项创建每日本地分支，保存双补丁和未跟踪文件，不自动提交或切换分支。实际规则与限制见 `DAILY_PROGRESS_PLAN.md`。
