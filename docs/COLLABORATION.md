# LAN Mesh 同事协作

星序工作版使用局域网双方直连，无需第三方服务器。知序不加载此模块，默认不启用网络。

## 连接 Evaluator 管理员

1. 员工在「日报与同步 → LAN Mesh 日报周报共享 → 连接评估员」填写姓名、部门，勾选允许共享的工作 issue，保存并启用。新增任务不会自动扩大授权范围。
2. 待连接就绪，点击「创建评估员授权」，填写该管理员名称。默认仅含所选 issue 的日报／周报摘要、人工进度与当前 Linear 状态快照，不共享原始聊天。
3. 如需管理员收集整份报告，**另外勾选**「完整日报、周报」。此范围可能包含 Demo、日常事项；管理员单独查看，不自动用于 issue 统计或模型问答。不同管理员的授权范围独立。
4. 私下交给管理员完整授权 JSON，核对姓名、范围和 TLS 指纹。管理员在最新版 Evaluator「员工与同步」发现员工设备并导入授权，点击「立即同步」；运行时每 60 秒自动增量同步。无法发现时手动填写员工 IPv4。
5. 工作 issue 记录在「日志问答／进度台账」使用；另行授权的完整文件在「完整日报与周报」查看。失败保留上次成功副本；撤销授权阻止后续读取，无法远程删除已收到的离线副本。

Evaluator 使用 `orbit-evaluator/v1`，UDP 45874 发现、员工固定复用的独立 TCP 端口传输，与同事讨论的 `orbit-lan-mesh/v2` 配对分开。旧星序的「我是管理员」只负责星序间报告文件副本，不能代替 Evaluator 授权。员工不必再运行 evaluator 分支，也无需迁移数据或改变 22 点 Linear 同步。

## 同事讨论与知识库

1. 双方打开「同事协作 → 局域网设置」，填写显示名称并启用。连接同一局域网，允许防火墙通过 UDP 45873 和本机 TCP 端口（默认 45874）。
2. 在发现的同事旁点击「请求配对」，通过当面或可信渠道核对两台电脑显示的配对码，双方分别确认。只发现设备不代表已经信任。
3. 选择同事后，点击「选择聊天并协作」，搜索并明确选择本机 Codex 聊天，预览并邀请。对方选择自己的聊天后确认协作；无需先创建或绑定任务。只交换聊天标识，聊天原文留在本机。
4. 双方确认后，后台使用系统当前 Codex 配置，从各自所选聊天的**完整历史上下文**整理专用项目知识库，而非只生成空模板或读取最近几天。代码负责选取单一聊天、排除子 agent / 系统 / 工具消息、脱敏、分段、缓存和版本校验，必要的文本归纳由 Codex 完成。生成进度在「我的知识库」显示，可切换界面或停止；失败可重试，重启不会自动重新发送生成请求。按照[轻量创建标准](PROJECT_KNOWLEDGE_STANDARD.md)，从背景、目标、已有资料与知识、思路、计划、当前进展开始，可自由删改或增加资料文件。
5. 点击「核对生成结果」，确认后保存为本地 `COLLABORATION.md`；生成期间的本地或外部编辑不会被覆盖，可复制所需内容手动合并。之后可在「我的知识库」编辑并保存本地，或打开资料目录由本机 Codex 整理。点击「预览并同步知识库」检查文件清单与文本差异，确认后共享此版本。初始生成草稿和后续编辑均不会自动发布；只有确认共享的版本才可被对方同步。
6. 双方在线时，「对方知识库」自动同步对方已共享的版本到本地独立副本；不会改写自己的笔记。旧版本保留，离线仍可查看。不同意见先保留，再按需人工整理进自己的知识库。
7. 「讨论」可发送围绕问题、计划和进展的消息；「聊天摘要」可将指定聊天的最近 24 小时或 7 天整理为本机草稿，结合双方知识库对齐内容。均需预览确认后发送，不自动向 Codex 发消息或执行收到的指令。
8. 「复制给 Codex 的上下文」提供双方本地知识库路径与讨论记录，由你粘贴到指定聊天继续处理。

双方各自维护知识库，只同步已共享的知识库版本，不接管代码工作区、不需要整目录互斥锁。资料上限 100 MiB、单文件 10 MiB、3000 个文件；排除 Git、环境、密钥与缓存。文件清单可预览，不能识别所有敏感内容，请在共享前核对。

局域网发现使用固定版本 LAN Mesh 的数据包与子网广播选择，不启动其远程执行 Worker。通信使用 TLS 指纹校验和设备签名；首次配对必须双方核对配对码，未配对设备不能读取任务、讨论或知识库。设备指纹变化时停止交换资料。

网络中断后保留待发送动作；连接故障会后台重试，内容错误可手动重试。消息使用稳定标识去重。文件校验失败、预览后资料变化、旧副本被修改时停止采用新副本，保留本机资料。网络停止或退出时结束本机监听与后台线程。

旧中心服务器记录仍保存在 `collaboration/state.json` 及原目录中；新版本使用独立的 `mesh-state.json` 和知识库版本目录，不自动迁移旧服务器凭据，不再连接旧服务器。已部署服务可停用并保留备份，不必删除历史数据。

首版需要双方同时在线完成配对、确认协作或接收新版本。局域网隔离、访客 Wi-Fi、VPN 或禁用广播的网段可能无法发现；不提供跨公网中继。结束协作会通知对方，双方保留已有本地记录。


## 日报周报共享与管理员收集

「日报与同步」和「工作日志与周报」里的「日志共享」入口，会打开「同事协作 → 日志共享与收集」。这项共享独立于项目协作，无需选择任务或聊天。

- 员工端：先与管理员设备配对，打开「共享设置」，勾选自动共享，指定管理员并确认。现有及后续生成的自动日报、下班日志、周报，以只读报告目录通过 LAN Mesh 提供给这台设备。
- 管理员端：与各同事配对，在「共享设置」开启「我是管理员，自动收集同事授权给本机的报告」。双方在线时自动收集；可按同事查看日报和周报文件数量、正文、收集状态，并导出 CSV 汇总清单。
- 共享范围为已结束的报告正文文件；待重试的报告会保留正文中的失败说明，正在生成或已取消的报告不收集。数据库、原始聊天、模型输入输出、Git 补丁、密钥和其他数据目录文件不共享。
- 原报告不搬迁、不更改 22 点 Linear 同步；管理员不能写回员工目录。源目录是 `daily/` 与 `daily/work-logs/`，共享视图分为「日报/自动」「日报/手动」「周报」。管理员副本按设备和版本保存在 `collaboration/report-collections/`，不覆盖同事的源文件。
- 停止共享立即阻止后续读取；管理员已收集的副本保留。网络中断、文件更新中或校验失败时保留上一版，恢复后重试。首次配对依旧需要双方核对相同配对码，不向整个局域网公开报告。

目录统计按报告文件计数，不将消息数量或模型总结当作工作完成率。管理员需使用含此功能的星序版本。
