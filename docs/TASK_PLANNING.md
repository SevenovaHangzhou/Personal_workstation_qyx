# 规划下一步 · Momo 0.6.1

## 交互

1. 打开任务详情，选择「＋ 规划下一步」。新建任务时也可先在「先记下几个方向」每行录入一件小事。
2. 每行写一个方向或小步，点击「加入并行方向」，表示这些步骤没有前置。选中已有小步后，点击「接在选中步骤后」，表示输入的每一项都以选中项为前置。
3. 在列表或图中选中小步，调整名称或勾选前置。多个勾选表示等这些前置都完成，再做这个小步；没有勾选的方向是本层起点。可引用同批新增的小步。
4. 图形自动从上到下布局：先后关系竖向展开，同层步骤横向并列，多个前置连入同一节点形成汇合。支持拖动、按钮缩放、Ctrl 加滚轮和「适应画布」。文字过长时悬停查看完整名称。
5. 点击「保存规划」一次保存全部编辑。输入框尚有未加入内容时会提醒，避免丢失；取消不创建任务。已有任务从详情删除，未保存草稿可在规划窗口移除。

详情自动显示本层 DAG 缩略图及实时状态；点击放大进入规划。缩略图双击节点打开子任务；节点如含更细步骤会显示数量，可逐层规划。图中的「本层步骤汇合」是路线终点，不会自动把父任务标为完成。

## 数据与边界

- 沿用任务 JSON v2，新增可选 `depends_on: [同父级任务 ID]`。旧任务缺少该字段时视为空，不根据标题或列表顺序猜测依赖，不改原有父子、聊天、issue 和仓库关系。
- 父子包含使用 parent_id；先后依赖使用 depends_on。每个步骤仍是独立任务，可继续拆分；同层依赖不跨父任务，以免把包含和先后混在一起。
- `/TaskService/apply_plan` 在已有 RLock 内校验基线、所有名称/引用/循环，再一次原子写入。并发变化若只改状态、笔记、绑定或内部子步骤，保存保留这些新值；同层名称、依赖或成员变化则拒绝覆盖并提示重新打开，当前输入保留。
- 删除前置任务前需明确解除其他步骤对它的引用；删除父任务前需先处理子任务。不会静默删除或重接依赖。
- 单次最多新增 100 项，本层规划上限 1000 项。每项名称 1–100 字。允许后向引用；循环、自依赖、重复前置、缺失前置和跨父级依赖均拒绝。
- 仅用于本地规划与图示，执行仍由用户决定；不会调度 Codex、自动提交任务、改变 issue 状态或新增 Linear 阻塞关系。工作小步按既有规则在晚间创建独立子 issue。
- 原生 PyQt5 QGraphicsView 画图，不增加 WebView、Graphviz、前端构建或网络下载依赖。

## 0.6.2 拖入连接

- 拖到卡片中部显示连接高亮，松开后选择「作为子步骤合入」或「接在此任务之后」；取消不改关系。卡片边缘及间隙仍用于排序。
- 子步骤改变包含关系，后续步骤建立同层显式前置并保留已有有效依赖；根级任务也可形成串并联路线，详情有原生路线缩略图及放大入口。
- 整棵原子树保留。跨分类、父子循环或依赖环拒绝；改变层级会影响已有前后依赖时，需要先明确调整，不静默删除依赖。
- 看板跨列可连接卡片中部，保留原状态；跨列间隙不会触发状态变化或排序。
- 只有工作任务记录 issue 父级待同步版本。下一次 22:00 同步已有 issue 的父级，不创建第二个 issue；旧日报的重试不会提前发布 22 点之后的层级调整。
