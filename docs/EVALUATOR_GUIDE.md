# 日志评估使用手册

这是 `evaluator` 分支的原生桌面功能，入口是侧栏「日志评估」。不做验收或员工评分，新的评估流程不写回 Linear。

## 启动

需要 Python 3.11+、项目运行时和 `requirements.txt` 依赖（新增 `cryptography`）。

- Linux：`./run-evaluator.sh`
- Windows：`./run-evaluator.ps1`
- 指定解释器：设置 `MOMO_PYTHON`；也可直接 `python evaluator.py`。

评估开发入口默认使用独立的 `Sevenova/OrbitEvaluator` 数据空间，首次打开为空；不会自动迁移工作版资料，也不会由正式 OTA 替换。开发入口会直接打开评估面板。

最新版星序员工端直接从「连接评估员」共享，无需切换分支。仅在需要用 evaluator 分支兼作员工端时，先从原星序托盘完整退出，再用这个分支启动原工作空间：

```bash
./run-evaluator.sh --data-dir "$HOME/.local/share/Sevenova/OrbitWork"
```

Windows 用相同的 `--data-dir` 参数指定自己的工作数据目录（通常在 `%LOCALAPPDATA%\Sevenova\OrbitWork`）。同一空间只能运行一个实例。试点前请备份该数据目录；评估副本另存于该空间的 `evaluation/`。

## 员工端：开放哪些日志

### 使用正式星序员工端（已接入）

员工无需切换到 evaluator 分支。最新版星序从「日报与同步 → LAN Mesh 日报周报共享 → 连接评估员」选择工作 issue 并启用共享，创建给指定评估员的授权。管理员在本应用「员工与同步」导入并同步，随后可直接使用日志问答、进度台账和员工名册。两端使用同一 `orbit-evaluator/v1` 协议、固定证书与独立可撤销授权。

完整日报、周报须由员工在创建授权时**另行勾选**，导入时会显示这个范围。管理员在「完整日报与周报」查看已校验的本地副本，支持自动收集后续文件、离线阅读和失败保留上次版本。完整文件可能含 Demo 和日常内容，单独保存，不自动作为 issue 进度证据或 Codex 问答上下文。默认只有工作 issue 记录；不能从完整 Markdown 猜任务归属或完成百分比。原有授权不会自动升级，扩大范围须重新创建并导入授权。

修改共享任务会在后续成功同步时收窄 issue 记录；撤销整个授权后阻止后续读取。离线副本无法远程销毁，完整报告历史暂不自动清理。员工端和管理员端都需要使用此次更新后的版本。

### 使用 evaluator 分支兼作员工端

1. 打开「我的共享」，填写姓名和部门。
2. 勾选需要共享的工作 issue，启用组织共享并保存。只有已关联真实 Linear issue 的工作任务可选；Demo、日常和未绑定任务不导出。
3. 等待服务就绪，点击「创建评估端授权」，为该评估人员单独生成一次授权。
4. 私下交给评估人员完整授权，并核对姓名和 TLS 指纹。不要把包含 token 的授权贴到公开 issue。

系统从已有日报、手动日／周报账本导出该任务的摘要与人工进度证据，不共享数据库、原始聊天、压缩中间文件或 Git。混绑多个任务的聊天不会直接导出，避免夹带未授权内容。摘要未完成会明确显示缺口。

每个评估端都有独立授权，可在此撤销。撤销阻止后续读取；评估端收到拒绝时隐藏该员工资料。若评估端离线，无法远程销毁其已有副本。

## 评估端：同步与提问

1. 在「我的共享」填写评估人员名称，启用评估端并保存；不需要启用自己的组织共享。
2. 「员工与同步」会自动发现局域网员工。选中员工后导入其授权，核对 IP、端口和指纹。自动发现受网络限制时，可手工填写员工 IPv4。
3. 点击「立即同步」。运行期间每 60 秒重试；只下载新增或变化的日志，完整校验成功后更新同步时间。
4. 在「日志问答」选择员工和 issue。点击「日期范围」可填起止日期，按本机时区包含结束日期当天；留空表示全部已有副本。
5. 「本地检索与统计」不调用模型；「Codex 问答」会先询问是否把所选证据发送给系统当前 Codex 配置的模型。可随时停止，其他页面仍可使用。
6. 「证据来源」查看实际引用的日期、记录 ID 与哈希。数量统计覆盖所有匹配记录，问答正文只使用有限片段，不能据此声称读过全部日志。

员工离线时仍可查询最后成功副本。查看每人的同步时间与错误信息；日志周期与同步时间不同，离线不等于没有新进展。共享清单变化会清空旧问答，提示重新检索。

## 员工、设备和 Linear 对应

「员工与设备」由评估端本机维护，与共享授权分开。先启用评估端，再按以下顺序整理：

1. 「员工名册」新建员工，填写姓名、部门与启用状态。同名员工由独立 ID 区分，不自动合并。停用保留历史，不撤销设备授权。
2. 在原「员工与同步」完成设备配对后，到「设备归档」选中来源设备，将它明确归入员工；可以备注「办公室台式机」「笔记本」等。一名员工可有多台设备。已有配对不会自动创建员工，归档前显示为未归档来源。
3. 「Linear 账号」选择员工，绑定工作空间 slug 和 Linear 用户 UUID。可从已同步的负责人账号候选填入，也可手动填写；不需要 API key，不根据姓名、日志作者或当前登录用户猜负责人。同一工作空间的同一用户只允许归属一个员工。
4. 员工详情分别展示负责的 issue 与日志贡献、各 issue 的状态／百分比、最近日志和已整理的阻碍，不计算员工总完成率。在「日志问答」选择名册员工，可同时查询其多台设备；也可单独选择一个设备来源。

首次归档会将该设备已有的可见日志归入所选员工。之后以「设备 ID + 日志记录 ID」固定首次归属，日志修订不会改人。设备转移给别人后，已归档日志仍归原员工，之后首次同步到的新记录归新员工；因此迟到补传的旧记录应在转移前先同步核对。解除归档不修改既有日志归属。

设备表的「已发现／未发现」来自局域网广播，不是员工出勤或确定在线状态；成功同步时间另列。设备地址、证书指纹与授权继续独立校验，修改名册不能扩大可读取范围。

负责人依据仅采用 issue 明确的 Linear `assignee_id`。旧记录或尚未刷新的员工端任务缓存可能没有该字段，此时显示待核对；同周期来源冲突也不猜。员工端原有日报流程刷新 issue 后，再同步可取得候选。绑定账号本身不会联网读取或写入 Linear。

## 进度与本机更新

「进度台账」按 issue 展示人员、状态快照和开发进度。

- 选择父 issue，点击「设置子 Issue 权重」，核对完整直接子项清单和相对权重后保存。未同步的子项可先填真实 issue UUID，资料到齐前保持待估。
- `completed` 计为完成，其他有效活动状态计为未完成；取消项从分母排除，不算完成。
- 多层子项逐层归一化。例如父项 A60／B40，A 下 A1=20／A2=30，则最终权重为 A1=24、A2=36、B=40，父子不重复计算。
- 未拆分、子项缺资料、父子关系冲突、空状态或全部取消时不猜百分比。叶 issue 仅展示 Linear 状态。
- **状态取自员工端任务当前缓存，随共享日志同步，并非实时读取 Linear，也不是历史时点状态回放。** 「最早依据日志」表示计算依据所关联的最早日志周期，员工列表另列最后成功同步时间；这两个时间都不代表 Linear 状态实际读取时间。员工端原有日报同步会刷新绑定 issue 的缓存；本版未新增独立的实时状态刷新入口。

「记录进展」可据日志填写摘要、阻碍与下一步，至少引用一份该 issue 的当前日志。保存编辑人、时间、证据版本与修改历史。日志更正后提示来源版本变化；撤回范围的派生记录不再出现在当前查询里。不会自动修改个人任务状态或远端 Linear。

## 汇报资料

员工在「我的共享」选择已有的汇报根目录，选中任务后点击「打开选中任务汇报目录」。星序创建 `<根目录>/<任务UUID>/` 并写入绑定标识；将汇报资料放在此目录中。

评估端在「汇报资料」选择任务，读取在线列表。UTF-8 的 txt、md、csv、json 支持最多 2MiB 文本预览；图片和其他文档仅显示元数据，不自动下载或 OCR。每个目录最多 500 份文件，单份文件最大 100MiB。

附件只在员工在线、应用运行且任务仍共享时可读，关闭查看器清空预览内存。不共享隐藏文件、凭据、证书、数据库、链接或目录外文件。任务换绑 issue 后拒绝沿用旧资料标识，需要人工整理。

## 连接排查

- 发现为空：确认双方同一局域网，允许 UDP 45874；也可手工导入 IP。
- 无法同步：确认员工共享开启，并允许员工端显示的 TCP 端口。端口在该数据空间首次启用后固定复用。
- 指纹不符：不发送凭据，不自动信任新证书；向员工重新核对授权。
- 未授权：原授权已撤销或 token 无效，需要员工新建授权。
- 日志为空：任务须明确共享且绑定真实 issue，并已产生可导出的日报或手动工作日志。未授权／混绑资料不会作为空摘要偷偷传输。

本版没有组织登录账号或中央服务器，名册保存在评估端本机。员工授权限定读取范围；不同评估电脑的副本和名册互不自动共享。副本与历史暂不自动清理，新的组织保留政策另行确认。
