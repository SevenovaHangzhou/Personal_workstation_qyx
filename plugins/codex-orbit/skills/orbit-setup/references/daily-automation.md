# Codex 每日更新日报

安装后由 MCP 初始化指令自动触发，也用于首次设置或补建日报任务。自动触发只完成日报创建，不打开连接卡片，不立即采集，完成后继续用户原任务。用户已授权安装后的每日自动日报时直接完成流程，不重复询问是否创建。

1. 调用 `prepare_daily_automation`。`state=waiting` 表示另一个会话正在完成创建，本会话停止创建流程并继续用户任务，不轮询。创建租约 15 分钟后可由新会话恢复，恢复时仍先查重。`ready/registered` 时返回 `command` 是已安装的稳定采集命令，`data_dir` 标识数据空间，`config.time` 默认本机每天 00:00，`config.enabled` 保留原停用偏好。保存 token。
2. 有 `automation_id` 就用宿主 `automation_update(mode=view)` 读取；同时按宿主规则检查已有自动化配置中的“星序 · 每日更新日报”及相同数据目录。复用同一任务，不根据名称覆盖不同空间的任务。创建结果不明确时先查重，不再次创建。
3. 使用宿主 `automation_update` 创建或更新任务，时间使用上一步的本机时间。遵循宿主类型规则，默认 thread heartbeat；用户指定独立项目任务时再用 cron。已有任务不因重新安装而改变用户修改的时间、暂停状态或通知偏好，使用完整原字段更新。
4. 提示词说明：运行返回的准确 `command` 参数列表，只更新此数据空间的到期日报，失败周期由采集器幂等补跑。只处理任务已绑定聊天和结构化结果；不拉取、领取或创建新任务，不修改 Linear，不发消息，不把原始聊天写进共享资料。报告处理周期、成功/待重试状态和产物目录；没有到期周期或正在运行时如实说明。命令路径安全引用，不把 JSON 文本当 shell 转义。
5. 创建或更新后用 `mode=view` 读回准确 ID，核对时间和执行提示；成功后调用 `confirm_daily_automation(token, automation_id, host_verified=true)`。插件此时才停用旧系统定时器并记录 Codex 自动化 ID。失败时用原 ID 和 token 重试，不创建第二项任务。

没有宿主自动化工具时，说明“插件已安装，日报任务将在 Codex 桌面加载插件后完成创建”。不直接编辑自动化 TOML 或 Codex 数据库，不宣称已注册。CLI 用户明确选择独立系统调度时可用安装器 `--schedule-backend system`。

时间和暂停状态以 Codex 自动化为准；修改时使用宿主工具并保留其他字段。采集周期边界仍为安装时配置的时间，不因修改运行时间重新切分已生成日报。原生卡片用于查看采集结果及手动补跑。

`--no-schedule` 关闭安装后自动创建；用户明确要求补建时仍可执行本流程。已确认的任务即使被用户暂停或删除，也不自动重建。
