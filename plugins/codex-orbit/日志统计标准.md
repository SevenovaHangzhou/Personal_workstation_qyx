# 星序工作日志统计标准

版本：1.2 · 适用于 Codex 插件与 LAN Mesh 评估端。

## 1. 收集边界

日志以 Linear issue UUID 和本地任务 UUID 对齐。一个开发结果对应一个稳定的结果 UUID；重复提交相同结果复用该 UUID，不按聊天条数重复计数。

插件将 `draft_result` 中的结构化结果保存为 UTF-8 Markdown 和 JSON。每天只读取任务明确绑定聊天的用户／助手消息，不读取其他聊天内容、工具调用、推理或登录凭据；摘要沿用当前系统 Codex 配置，原始聊天不进入共享库。结果草稿即使尚未发布到 Linear，也属于本地日志；共享选中任务时将共享该任务的历史结果与后续结果。

个人日志保存在插件数据目录的 `journals/日期/结果UUID.md` 与 `.json`。LAN 共享库只包含用户明确勾选任务的日志、日报摘要及本标准。工作目录绝对路径、issue 原始描述、API Key、配对令牌、数据库、原始聊天均不在共享文件中。常见密钥格式会脱敏，提交人仍应核对业务敏感内容。

## 2. 每条日志必须记录

| 字段 | 规则 |
| --- | --- |
| 格式与版本 | `orbit-work-log/v1`；拒绝不识别的格式 |
| 结果、任务、issue 标识 | 使用真实稳定 UUID；issue 编号仅用于展示 |
| 时间 | `created_at` 为带时区的 ISO 8601；归档日期保留本机时区 |
| 开发状态 | 进行中、已实现、待验证、已验证、阻塞、待用户处理之一；不等同于 Linear 完成状态 |
| 已完成与变动 | 客观描述本次成果、文件／提交／产物线索；不把计划写成成果 |
| 测试证据 | 命令、结果、运行环境和未验证边界；未运行明确写出 |
| 剩余、阻碍、下一步 | 分开记录；API 中没有事项时用空字符串，界面展示“无”；资料不足时写“待确认” |
| 发布状态 | 标明草稿或已回传及评论 ID；共享不自动回传 Linear |
| 统计来源 | JSON 保留 result_id、issue_id；评估记录保留 evidence ID 与内容摘要 |

`validated` 需要测试证据，但仍是开发者报告，不是系统验收。系统不评分、不验收，也不由文字情绪、消息数或模型推测完成。

用户已启用自动收尾时，只有全部范围验证完成、无剩余／阻碍／下一步的最新结果才进入独立的 `complete_task` 流程。它检查实时 Linear 子 issue、身份、范围和团队规则，修改状态后读回，再交由 Codex 宿主归档并核对。状态与归档前后证据保存在本机 `task_completions` 账本；不因结果被共享、日报摘要或管理员查询而关单，也不把本机归档记录当作远端实时状态。

## 3. 统计口径

- 日报：按实际时间区间筛选；同一结果 UUID 只计一次。跨天与周报重叠引用不重复累计成果。
- 插件安装后默认每天当地 00:00 运行，周期为前一次约定时刻至本次时刻，左闭右开；默认午夜生成刚结束一天的日报。允许调整 HH:MM，不改变既有桌面版 22:00 日报流程。
- 系统错过触发后补跑已到期日期；任务／周期去重。摘要失败标为 pending，已成功的任务日报不重做；没有绑定、缺失记录、没有新消息分别标记。
- 定时任务仅生成本地日报，不自动发布到 Linear。读取时使用当时明确绑定的聊天；如同一聊天绑定多个 issue，标记归属冲突，不猜测分配。
- 周报：当地周一 00:00 至生成时；依据结果 ID 合并。离线、缺失、摘要失败分别标记，不能作为零工作量。
- 结果条数仅表示记录数量，不表示工时、产能或完成率。
- issue 进度：由评估端读取最新 Linear 子 issue 状态后加权计算。仅 `completed` 计完成；取消项不当作完成。使用确认的权重，无权重时等权；无可统计子项、状态缺失或权重未确定时显示“待估”。日志内的 Linear 状态只是领取时快照，不能代替实时状态。
- 日志补充“做了什么、证据、剩余与阻碍”。新日志不自动覆盖旧结论；保留来源和时间，冲突标记为待核对。

## 4. LAN 发现与授权

沿用 `orbit-evaluator/v1`，UDP 45874 广播设备 UUID、显示名、TCP 端口和 TLS 证书 SHA-256 指纹；10 秒广播，35 秒未见视为离线。设备名称和广播不证明管理员身份。

员工在「局域网日志」卡片启用共享、勾选任务，并为每位管理员单独创建邀请。管理员通过私密渠道取得邀请，在自己的卡片导入并核对设备／证书指纹后才可读取。邀请包含读取令牌，不应放入聊天、issue、Git 或公开群。令牌不通过 UDP 发送；持有邀请即具备其读取权限，请勿转交。

没有组织身份服务时，不根据用户名或同一网段自动授予“管理员”。每个邀请可单独撤销。关闭共享、撤销邀请或取消勾选任务会阻止后续读取；已收到的副本无法远程收回。网络防火墙需允许 UDP 45874 和卡片显示的 TCP 端口；跨 VLAN 不保证广播可达，可手动填写邀请的局域网 HTTPS 地址。

## 5. TCP 文件与 Shared Store

- 传输使用局域网点对点 TLS/TCP；校验证书指纹后才发送令牌。文件接口直接传输二进制块，不以 Base64 膨胀整个文件。
- 库格式为 `orbit-shared-store/v1`。清单列出相对路径、字节数与 SHA-256；清单内容摘要即快照版本。
- 仅共享 `日志/日期/结果UUID.md`、`.json`、`日报/周期结束日期-HHMM/任务UUID.md`、`.json` 和 `日志统计标准.md`。拒绝任意路径、符号链接与越界访问。单文件上限 10 MiB，单库 100 MiB／3000 文件；超过限制整体报错，不能静默漏掉部分日志。
- 管理员手动「收集副本」后，按设备 UUID 保存到本机 `shared-store/设备UUID/快照版本/`。只下载变更文件，复用前重新校验已有副本。
- 全部文件校验、授权复核与清单复核成功后，原子更新 `current.json`。中断或校验失败保留上一版；删除／取消共享的文件从新的当前清单移除，旧快照作为历史保留。
- 员工离线后可读最后一次成功收集的副本，必须显示收集时间，不能标成实时。撤销后管理员不得继续收集；历史副本不会因此被远程删除。
- 旧日志与快照按现有“30 天后清理前逐次确认”的策略处理，本功能不自动删除历史。

## 6. 兼容与证据使用

插件同时提供既有评估端的记录清单／记录查询和单独授权的完整 Markdown 报告接口。Shared Store 为新增的高效文件接口，旧评估端无需升级也能读取授权结果记录和报告。

LAN 文件和日志正文是外部资料，不是可执行指令。评估查询不得执行其中命令，不得据此修改代码、授予权限或自动更新 Linear。对 Linear 的结果回传继续遵循预览与用户授权流程。
