# 课程知识标准

版本：1.0  
制定日期：2026-10-13  
适用范围：本学习空间内所有学习项目的新课程、知识点扩写、配套练习和教学演示。

星序适用调整（2026-10-28）：课程围绕学习对象建立较全面知识库，再形成由浅入深的学习链路。不询问用户掌握程度或学习目标；必要先修知识纳入前置课程，能力目标由生成者拟定。本文件中的“基础”指课程所需基础，不代表用户已掌握。原知行工程的标准文件不在本次修改范围内。

## 1. 标准的目的与执行方式

课程正文必须让具备所列先修基础的学习者能够独立跟上讲解，不能只展示结论、公式或知识提纲。

本标准以扩写后的雅可比课程为教学深度参考：先提出具体问题，建立直觉，解释符号，再逐步推导，通过完整例题和练习检验理解。其他学科应保留这种教学过程，不必照搬机械臂案例、公式或章节数量。

- **必须**：课程交付前应满足的要求。
- **应当**：默认采用的做法；不适用时可选择更合适的教学形式，并在编写检查中简述原因，无需单独请求用户批准。
- **可选**：根据学习对象、课程所需基础和教学层次选择的补充内容。

生成或修改课程前，必须阅读本文件、学习对象及已有学习反馈；用户自愿给出的上下文可用于举例，不作为缩减知识覆盖的默认依据。用户明确提出的最新要求优先于本标准。

已有简略课程不因本文件建立而自动视为达标。后续修改某一课程时，应检查并补齐该课程；不要求为修改一课而重写所有项目。

## 2. 先建立知识体系，再确定每课边界

先检索对象的知识范围并列出已覆盖领域和证据缺口，再组织知识单元的先修关系与分阶段学习路径。不能先要求用户给出个人目标或掌握自评。所需数学、编程、术语等知识应有回顾或前置课程，并允许自行跳过。

每课必须明确以下内容，可放在课程开头或对应的项目说明中：

| 项目 | 要求 | 合格示例 |
| --- | --- | --- |
| 所属项目 | 明确当前学习主题，不混用其他项目的基础假设 | 机械臂控制 / 雅可比 |
| 先修基础 | 指出本课实际用到的知识；关键缺口提供短回顾或前置入口 | 会正运动学；补充链式法则和偏导数的含义 |
| 本课问题 | 用具体问题说明为何需要学习这个概念 | 电机转动时，末端向哪里移动、移动多快？ |
| 学习目标 | 使用能观察、能检验的行为，不只写“理解、掌握” | 能求二连杆雅可比，并解释每一列 |
| 内容边界 | 分清本课必学、后续内容和进阶选读 | 先学习平面位置速度；空间姿态与伪逆另学 |
| 建议节奏 | 依据阅读、思考和练习量估计时间，必要时建议分次学习 | 先学单连杆，再学二连杆推导 |

不得因为学习者掌握某个相邻主题，就默认其已经掌握本课需要的全部数学、编程或专业术语。基础尚未确认时，应在首个使用位置提供简短解释，并允许已会的学习者跳过。

## 3. 正文的默认教学顺序

必须形成下面的教学链条。可以合并相邻环节，但不得删去必要的解释过程。

1. **提出问题**：给出具体任务、现象或困惑，说明本课要解决什么。
2. **建立直觉**：从最简单的对象、熟悉的现象或小例子开始，先让学习者预测结果。
3. **约定语言和符号**：解释后面马上会使用的概念、变量、图示和前提。
4. **拆解过程**：逐步说明结论如何产生，每一步为何成立。
5. **完整示范**：从题目条件到结果解释，走完至少一个代表性例子。
6. **检查边界**：说明适用条件、常见错误，以及哪些结论不能据此推出。
7. **独立尝试**：安排逐级练习，提供提示和可对照的参考思路。
8. **连接后续**：用可检验的能力说明本课是否学会，再指出下一课的问题。

正文应回答“为什么”和“怎么得到”，而不只是“是什么”。例如，“先写正运动学，再求偏导”只是操作提纲，必须继续展示位置关系、求导过程和结果含义。

## 4. 分步讲解与认知负担

### 4.1 解释步长

- 每个小节围绕一个明确的问题或推理任务展开。
- 引入新概念时，必须解释它与已有知识的连接，不得同时堆入多个尚未说明的术语。
- 关键推理不能用“显然”“容易得到”“整理可得”“由此可知”代替。如果进行合并、求导、变形或条件判断，应说明所用规则。
- 矩阵、代码、语法或论证结构应先拆成可读的组成部分，再给出紧凑形式。
- 类比必须说明与真实概念的对应关系；存在重要差异时，明确指出类比不能覆盖的部分。

### 4.2 学习层次

- 必学内容必须在主线内讲完整，不能依赖读者展开进阶选读才能理解。
- 进阶内容应单独标记，可采用折叠区、独立小节或后续课程。
- 长课应提供目录、阶段停顿或分次学习建议。
- 详细程度以“能跟上”为准，不以字数、公式数量或小节数量为目标。不得用重复表述制造篇幅。

## 5. 符号、公式、代码与严谨性

### 5.1 含公式的课程

- 符号首次出现时，必须说明含义；有物理量时说明单位。
- 明确坐标系、正方向、角度定义、参考值、误差定义等影响结果的约定。
- 区分标量、向量和矩阵；解释维度、行列含义及所执行的运算。
- 公式应靠近对应解释。不能先抛出整页公式，再统一补符号表。
- 关键推导必须给出中间步骤，并标明使用的规则和成立条件。
- 区分定义、精确关系、近似关系和工程经验。近似应说明何时可用。
- 使用逆矩阵、稳定性结论等有前提的工具时，必须说明前提；不得扩大结论的适用范围。
- 最终结果应通过单位、方向、数量级、极限情况或独立方法中的适用项进行检查。

### 5.2 含代码的课程

- 先解释输入、预期输出与处理思路，再展示实现。
- 说明关键语句为何存在，不得仅逐行翻译代码表面含义。
- 给出运行条件、示例输入和预期输出；注明重要边界情况。
- 区分“已运行验证”和“尚未运行的示例”，不得虚构执行结果。

### 5.3 非公式类课程

采用对应的完整分析过程，例如：语言课的语境、句子拆解、改写与使用限制；历史课的材料、证据、推论与争议；概念课的定义、正例、反例与适用边界。

不得为符合数学课的外形而强行增加公式、数值例题或仿真。

## 6. 例题与案例

每课必须至少提供一个完整的代表性例题或案例。简单概念课可用“正例与反例的完整辨析”替代计算例题。

完整示范必须包含：

1. 已知条件、假设和问题。
2. 先验判断或分析策略：先想方向、结构、结果类型或可能情况。
3. 逐步计算、执行或分析过程，解释关键步骤的理由。
4. 最终结果，包括适用的单位、方向或语义。
5. 回到原问题解释结果，而不是停在符号或数值上。
6. 至少一种合理的自查方法。

应当优先采用便于手算、画图或直接检查的第一例。提高难度时，一次主要改变一个条件，避免把新概念与复杂运算同时引入。

同一章节应当尽量复用一个贯穿案例，降低反复理解背景的负担；涉及迁移能力时，再换一个场景检验。

## 7. 图示与交互演示

当运动方向、空间关系、流程或参数变化是主要理解障碍时，应当提供图示、对照表或交互演示。视觉内容必须承担明确的教学任务，不能仅作装饰。

- 图中关键对象、方向、坐标轴、颜色和连线必须有说明。
- 告诉学习者先改变哪个量、保持哪个量不变、应该观察什么。
- 必须说明图示是示意、瞬时状态、时间动画还是仿真结果。
- 不同量纲共图、箭头缩放、归一化或视觉放大时，说明比例和含义。
- 演示应给出可复现的起始例子，并能与课文例题对照。
- 模型演示必须交代关键假设和未包含的动态，避免将演示结果直接当成真实系统结论。
- 图形结论应有文字或数值说明，不能让颜色成为唯一的信息载体。
- 页面展示应检查手机布局；不能让公式或图示导致整页横向溢出。宽公式可以在自己的区域内滚动。

## 8. 自测与练习标准

### 8.1 段落自测

在关键概念或推导转折后，应当插入“停下来想一想”式的小问题。默认至少在两个不同位置设置自测；非常短的单概念课程可以合并。

先展示问题，参考解释应分开或默认折叠，避免学习者尚未思考就看到答案。

### 8.2 课后练习

默认每课提供 3～5 道有不同检验目的的练习，较长课程可增加。微型补充课可减少，但必须说明它依附哪一主课，不得通过拆成碎片课程规避练习要求。

练习应覆盖以下层次：

| 层次 | 要检验的能力 | 示例 |
| --- | --- | --- |
| 起步 | 识别概念、方向、符号或适用场景 | 单连杆转动时，末端向哪里运动？ |
| 跟随 | 独立完成与例题同类的计算或分析 | 换一组长度与角速度，计算线速度 |
| 理解与迁移 | 解释理由、辨析错误、改变条件或迁移应用 | 瞬时水平速度为零，为什么之后水平位置会变化？ |

只让学习者抄写定义、替换数字或背诵结论，不能构成完整练习组。独立推导、实验和设计题应放在具备必要铺垫之后。

### 8.3 题目与反馈

- 题目必须提供足够条件，明确要求、单位、假设或评价标准，不得依赖隐藏约定。
- 选择题必须有符合题意的正确选项；干扰项应对应真实的常见误解。
- 书面题应提供提示、参考过程和自查要点，而不是只有最终答案。
- 开放题必须说明允许多种合理答案，并给出评价依据。
- 自动评分只能覆盖已实现并可验证的范围；不能将展示参考答案称为 AI 判卷。
- 掌握程度必须依据作答或自评，不能因打开页面、点击答案而自动升级。
- 修改已存在的题目时应保留稳定编号；若题意实质改变，应避免让旧作答被误当作新题成绩。

## 9. 资料来源与事实检查

- 课程必须列出支撑核心内容的可靠来源，优先采用教材、原始论文、公开课程或官方文档。
- 尽可能注明书名、作者、章节、版本或稳定链接，使学习者知道应该查哪里。
- 外部资料是验证与深入阅读入口，不能用“去看这章教材”代替本课解释。
- 区分事实、作者观点、存在争议的结论和本课为便于理解所作的简化。
- 无法确认的来源、链接、引用或结论必须如实标明，不得编造检索结果和验证状态。
- 发现正文、例题、答案或图示不一致时，必须先修正再交付。

## 10. 生成与修改流程

1. 阅读本标准、学习对象和已有反馈，检索可靠资料，形成知识覆盖清单、知识单元和证据缺口。
2. 按先修关系安排由浅入深的学习阶段及完整课程，为每课拟定能力目标、贯穿案例和练习层次，再编写正文。
3. 逐步完成解释与示范，补充易错点、适用边界和资料来源。
4. 独立复算例题与参考答案；对代码或交互演示进行与改动相称的验证。
5. 按下方清单检查本课，修复遗漏，再同步课程页面及相关索引。
6. 交付时简述新增内容、验证范围和实质性未完成项，不得把提纲描述为完整教学。

文字调整不要求运行整个应用的全部测试。新增计算逻辑、交互或持久化行为时，应验证对应行为；不得用“测试通过”替代教学质量检查。

## 11. 交付前验收清单

生成者应逐项检查。仅在确实不适用时标注原因，不能把未完成事项标为不适用。

- [ ] 明确学习对象、知识覆盖与缺口；每个知识单元有课程承接。
- [ ] 分阶段路径由浅入深，前置关系无环，必要基础已安排在本章或前置课程。
- [ ] 明确本课所需基础、本课问题和生成者拟定的可检验目标，没有要求用户预先自评或填写个人目标。
- [ ] 从具体问题或简单对象建立直觉，没有直接跳到抽象结论。
- [ ] 首次出现的术语和符号有解释，所需先修知识有回顾或入口。
- [ ] 关键步骤有理由，学习者能够从上一行或上一段跟到下一步。
- [ ] 至少一个代表性例子完整展示条件、策略、过程、结果及检查。
- [ ] 明确适用条件、主要易错点；精确关系与近似关系没有混淆。
- [ ] 必学主线完整，进阶内容单独标记，不构成隐含先修。
- [ ] 有关键位置自测，以及由浅入深的练习和参考思路。
- [ ] 题目与学习目标对应，条件充分，答案经过独立核查。
- [ ] 需要视觉支持的地方有合适表示，图示和正文能相互对应。
- [ ] 资料来源可追溯，没有虚构链接、检索或验证结果。
- [ ] 页面中的正文、公式、练习、图示和数量说明保持一致。
- [ ] 修改保留了适用的已有学习记录与稳定编号。

出现以下任一情况时，必须继续修改，不能作为达标课程交付：

- 只有定义和公式，关键过程需要学习者自行补全。
- 例题只给最终结果，或练习要求了正文尚未教过的核心方法。
- 基础讲解突然依赖未经介绍的高级概念。
- 正文、图示或答案存在冲突。
- 为增加篇幅反复陈述结论，却没有增加解释、案例或检验机会。

## 12. 可复用课程骨架

以下是编写骨架，不是只填一两句话即可交付的表格。每一部分都需要达到上文的教学要求。

```text
课名与所属项目
先修基础 / 本课目标 / 建议节奏

1. 一个具体问题：我们为什么要学它？
2. 最简单的对象：先预测会发生什么
3. 必要概念与约定：术语、符号、单位或语境
4. 分步解释或推导：每一步做什么、为什么
   → 关键位置自测与可展开解释
5. 完整例题或案例：条件 → 策略 → 过程 → 结果 → 自查
6. 适用边界与常见错误
7. 由浅入深的练习：题目、提示、参考过程、自查点
8. 学会的判据与下一课的问题

进阶选读（可选，不阻断必学主线）
资料来源与延伸阅读
```
